# Pretty Up Resource PRD

将视觉参考转译为美术可制作、产品可验收、用户可理解的资源定义。先判断资源，再写需求，最后命名。

## 工作原则

- 把用户对图片关系、资源数量、目标市场和产品限制的明确说明视为最高优先级事实。
- 只把图片中可观察的内容写成事实。无法确认的动态、参数、素材关系或实现方式标为假设或待确认。
- 区分目标效果参考、风格/情绪参考、展示版式参考、Before/After、多视角和重复素材。
- 抽象审美词必须落到位置、范围、色彩、材质、层级、强弱、参数或可观察结果。
- “网感”不等于堆砌热词。它需要同时体现当下视觉语言、目标用户的自然表达和缩略图/产品列表中的传播效率。
- 保留人物身份、肤色深度和真实结构。除非用户明确要求，不用统一提白、模板脸或夸张重塑制造变化。
- 默认先给可派单的精简版本；复杂判断放到附录，不让解释淹没需求。

## 流程

### 1. 盘点输入

先建立内部素材账本：文件或图号、内容、在任务中的角色、所属资源、是否重复、确定性。

优先解决：

1. 有几个资源，而不是有几张图。
2. 多图是同一资源的多视角/多肤色/多人物，还是不同资源。
3. 哪些是目标效果，哪些只提供风格、构图或文案语气。
4. 哪些是 Before/After，配对是否可靠。

若歧义会改变资源数量、核心机制或交付范围，提出一个集中问题；否则采用最保守解释并标注假设。

详细方法见 [references/visual-analysis.md](references/visual-analysis.md)。

### 2. 选择资源模式

- 面部贴纸/装饰：关注造型、位置、尺度、跟随、遮挡、变形和多款区分。
- 局部妆效：关注底色、色调、材质、透明度、颗粒、光泽、边界、解剖结构和肤色适配。
- 一键美化/美容配方：关注同一审美身份下的模块组合、固定参数、自适应逻辑、跨人物验证和 Before/After。
- 配套短文案：先确定任务是情绪、痛点、选择互动还是效果承诺，只保留一个主方向。

读取 [references/resource-modes.md](references/resource-modes.md) 中与当前任务对应的模式；不要加载无关模式要求。

### 3. 锁定效果身份

用一句内部定义说明：`目标人群/场景 + 核心视觉机制 + 预期感受`。

再分三类：

- 固定项：所有样片都必须保持的资源记忆点。
- 自适应项：随肤色、脸型、光照、角度或画面尺度变化的部分。
- 禁改项：不得改变的人物特征、素材条件和产品边界。

不要在效果身份稳定前起名。

### 4. 写成制作规格

只选择当前任务需要的维度：形态与位置、色彩关系、材质与透明度、颗粒与密度、层次、光泽、结构结合、动态跟随、缩略图识别、跨肤色/脸型/场景适配。

输出应回答：做什么、做到什么程度、如何判断合格、什么情况算失败。用户没有提供尺寸、格式或参数表时，不得编造具体数值。

使用 [references/output-template.md](references/output-template.md) 选择派单格式。

### 5. 写文案和命名

在规格锁定后，从最强视觉记忆点和用户收益生成文案与名称。

- 文案像真实用户会说的话，避免品牌强行玩梗、空泛氛围词和连续感叹。
- 名称先满足效果贴合，再追求传播感。
- 中英文分别创作，不逐字硬译；检查长度、母语自然度、文化联想、负面含义和趋势寿命。
- 给一个首选和少量分方向备选，并解释首选依据。

涉及命名、海外市场或社媒文案时读取 [references/naming-and-copy.md](references/naming-and-copy.md)。

### 6. 验收自检

- 是否误把同一资源拆成多个资源，或漏掉重复素材？
- 是否明确固定项、自适应项和禁改项？
- 每个“高级、自然、氛围、网感、精致”等词后是否有制作机制？
- 是否覆盖正常视角、近景和缩略图中真正需要被识别的效果？
- 是否写了肤色、脸型、光照或场景适配中与当前资源有关的部分？
- 验收标准能否通过对照成品直接判断，而不是只表达主观喜好？
- 名称是否来自效果身份，英文是否检查过真实语义？

发现关键信息不足时，先输出已确定部分和一份短“待确认项”，不要用长篇问题阻塞工作。
