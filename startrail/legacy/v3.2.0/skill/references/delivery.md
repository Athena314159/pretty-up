# 交付
默认输出：任务与时间范围；近期上升候选；历史热点对照；每条如何用于任务；可追溯来源；证据缺口；本次新增/复用/刷新统计。
工作按决策问题分组，学习按作业/研究问题分组。地区分组仅在有比较价值时启用。
图文年份/数量规则：用户“再找N个”是新增，“整理N个”是总量。图文不含动态照片、GIF或仅视频封面；媒体不明不计图文。
需要Excel案例库时调用可用Spreadsheets技能：一行一案例、原始指标与日期数值类型、筛选冻结、原帖直链。按任务相关性与趋势优先级组织，用户明确指定排序优先遵循。
案例图片尽量嵌入最高可获取分辨率；只缩放显示、不降采样，长宽比完整。截图不能冒充平台原图；兼容转换须无损。检查数据行、案例、图片对象对应，缺图明确标记，检查首中尾布局与媒体尺寸。
格式文件不是必需。只要简答就直接回复，不强制Excel。未来趋势只能标预测，说明依据、置信度和反证条件。

## 网页交付位置与执行进程
界面分输入资料、流程、成果、记忆。用户图片/文件是输入，不算已分析证据；网页将原文件保存在本浏览器IndexedDB，任务包ZIP含本任务记忆、执行任务与附件。只有实际读取附件后才能分析内容，PDF/Office等网页不解析的文件不要声称已读。
学习工作皆可分Part交付：在对应tasks记录的results数组追加对象{id,step_id,part,title,status,content,source,updated_at,file_ref?,url?}。status=available是实际提供，needs_input是待决定；没有实际成果的Part保持待交付。文件引用须对应真实文件，HTTP链接须核验。生成Prompt/计划不代表该步骤完成。
workflow_progress记录真实状态pending/in_progress/needs_input/completed、note、artifact、updated_at和recorded_by。没有后台执行连接时只展示同步/手动记录，不模拟实时进度百分比。待决定信息单独显示且说明哪些独立工作仍可继续。
网页JSON仅含附件元数据，不能还原原文件。任务包携带附件二进制；若缺文件请用户重新提供。网页不自动跨对话发消息，不把复制按钮说成已派发。

## 面向员工和学生的界面契约（V3）
首页只收任务目标、资料和交付要求。不要把单一包袋课程的数量和步骤套给其他任务。包袋模板的执行Prompt以`references/profiles/bag-prompts.json`的common及Part 0—10为准，来源是“包袋设计作业流程”中的优化版execution-prompts.json；保留外观设计纠偏，不改回工程结构为主。
流程仅表示当前阶段：任务整理、资料研究、分析核验、成果交付；不要求用户逐步点击生成、手动验收来驱动常规流程。无执行服务时显示等待执行，不能模拟进行中。
主区首先展示实际可用方案与成果，清楚注明计划/预测/未核验、来源和缺口。Prompt是可选详情，默认折叠，只有点击时展开，并允许逐Part复制/下载；不要在初始页面铺满Prompt与操作规则。
每Part包含实际输入要求、执行要求、预期产物、验收条件、来源/版本与任务上下文。通用工作/学习规则按需生成；特定领域采用明确选择的模板。
实际成果需与Prompt分开存储；生成Prompt不算完成资料搜索、图像分析或文件交付。附件尚未读取时明确说明，历史记忆不得覆盖用户最新纠偏。

## 预览与核验截图
成果预览使用完整作品图，优先原帖图片文件，保持比例、原有水印及来源。不把浏览器边栏、评论或导航混进作品预览。只能截图时裁取作品区域并标明截图；不得裁掉作品内容。整页截图单独作为核验证据。检查下载/翻页后图像确已加载，图序与文件相符。
